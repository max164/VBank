# VBank — анализ предметной области

## 1. Назначение системы

VBank — внутренняя виртуальная банковская система для учёта денежных средств пользователей в нескольких валютах, выполнения внутренних операций, обработки ручных заявок и ведения аудита.

## 2. Границы предметной области

### В рамках системы

* пользователи и их статусы;
* роли доступа;
* счета и типы счетов;
* внутренние финансовые операции;
* ручные заявки;
* справочники;
* режимы работы системы;
* аудит значимых действий.

### Вне рамок системы

* внешние банки, платёжные шлюзы и реальные расчёты вне VBank;
* валютная конвертация;
* KYC, AML и комплаенс-процедуры;
* отмена проведённой операции;
* сложный многоэтапный процесс согласования.

## 3. Участники

### Клиент (`Client`)

Работает только со своими счетами, операциями и заявками.

### Оператор (`Operator`)

Обрабатывает заявки, управляет статусами пользователей и выполняет служебные действия в рамках полномочий.

### Администратор (`Admin`)

Управляет справочниками, режимами работы системы и аудитом.

## 4. Ключевые сущности предметной области

* **Пользователь (`User`)** — субъект системы, владелец счетов и инициатор действий.
* **Счёт (`Account`)** — средство хранения денежных средств пользователя в одной валюте и одного типа.
* **Тип счёта (`AccountType`)** — правило поведения счёта, включая возможность ухода в минус.
* **Валюта (`Currency`)** — справочная денежная единица.
* **Финансовая операция (`Transaction`)** — необратимый факт изменения денежных средств.
* **Проводка (`LedgerEntry`)** — учётная запись успешной финансовой операции.
* **Заявка (`Request`)** — объект ручного рассмотрения для действий, которые не выполняются напрямую.
* **Код причины (`ReasonCode`)** — справочник причин отказов и решений.
* **Настройка системы (`SystemSetting`)** — управляемый режим работы системы.
* **Журнал аудита (`AuditLog`)** — неизменяемый журнал значимых действий и результатов.

## 5. Основные сценарии

### 5.1. Регистрация пользователя

Путь регистрации определяется режимом `registration_mode`:

* `auto` — пользователь создаётся сразу;
* `manual` — создаётся заявка, пользователь создаётся после одобрения.

### 5.2. Открытие счёта

Путь открытия счёта определяется режимом `account_opening_mode`:

* `auto` — счёт открывается сразу;
* `manual` — создаётся заявка, счёт открывается после одобрения.

### 5.3. Перевод между счетами

Получатель перевода во внешнем сценарии определяется по номеру счёта.

Путь перевода определяется режимом `internal_transfer_mode`:

* `enabled` — перевод выполняется напрямую;
* `manual` — создаётся заявка, перевод выполняется после одобрения;
* `disabled` — перевод недоступен.

### 5.4. Пополнение и вывод

Пополнение и вывод управляются режимом `cash_in_out_mode`:

* `manual` — действия доступны только через заявку;
* `disabled` — действия недоступны.

Начальное значение режима для первой версии — `manual`. При `disabled` заявка на пополнение или вывод не создаётся.

### 5.5. Компенсация

Ошибочно проведённая операция не отменяется. Для корректировки создаётся отдельная компенсирующая операция.

## 6. Бизнес-правила

### 6.1. Правила денег

* деньги существуют только в рамках конкретного счёта и его валюты;
* сумма финансовой операции всегда больше нуля;
* сумма проводки хранится со знаком: списание отрицательное, зачисление положительное;
* переводы выполняются только между счетами одной валюты;
* проведённая операция не отменяется;
* корректировка выполняется отдельной компенсирующей операцией.

### 6.2. Правила отрицательного баланса

* уход в минус допускается только для перевода;
* уход в минус возможен только для типа счёта, где это разрешено;
* для такого счёта должен быть задан лимит отрицательного баланса;
* вывод не должен приводить к отрицательному балансу.

### 6.3. Правила заявок

* заявка существует только для сценария, переведённого в ручной режим;
* оператор принимает итоговое решение по заявке;
* одобренная заявка порождает результат предметной области;
* отклонённая заявка не меняет финансовое состояние системы.

## 7. Режимы работы системы

* `registration_mode`: `auto`, `manual`
* `account_opening_mode`: `auto`, `manual`
* `internal_transfer_mode`: `enabled`, `manual`, `disabled`
* `cash_in_out_mode`: `manual`, `disabled`

## 8. Инварианты предметной области

* один пользователь может иметь не более одного счёта одного типа в одной валюте;
* счёт можно закрыть только при нулевом балансе;
* заблокированный счёт не принимает новые операции и не закрывается, но остаётся видимым в истории;
* закрытый счёт не может участвовать в новых операциях;
* валюта операции должна совпадать с валютой всех затронутых счетов;
* компенсирующая операция всегда ссылается на исходную.
