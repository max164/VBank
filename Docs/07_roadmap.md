# Дорожная карта VBank

## Плановый контур

Смысл раздела:
Зафиксировать единый порядок ведения плановых документов VBank и разделить уровни детализации.

Состав планового контура:
- дорожная карта;
- журналы задач;
- планы задач;
- порядок управления переходами между ними.

Правило планового контура: Дорожная карта → Журнал задач → План задачи.
- Дорожная карта отвечает за направление, показывает вехи развития продукта, их смысл, ожидаемый результат и переходы между этапами.
- Журнал задач отвечает за состав работ этапа внутри одной вехи, но не описывает пошаговое выполнение отдельных задач и не заменяет журнал изменений.
- План задачи отвечает за исполнение одной конкретной задачи: цель, входные данные, шаги, проверки и ожидаемый результат.

## Этап 1. Требования и проектная основа

Состояние:
В основном готово.

Смысл этапа:
Зафиксировать, что представляет собой VBank, какие задачи решает система, где проходят её границы и какие правила считаются основными.

Подготовка перед началом этапа:
Собрать исходные идеи, заметки, ограничения и ожидания по системе. Привести их к единому виду, убрать противоречия, выделить устойчивые сущности, роли и сценарии. Провести уточняющие обсуждения по спорным правилам: пользователи, счета, операции, заявки, роли, аудит, режимы работы.

Задачи верхнего уровня:
- описание предметной области;
- техническое задание;
- доменная модель;
- модель данных;
- архитектурная структура;
- словарь терминов.

Ожидаемый результат:
Есть согласованная проектная основа, от которой можно строить API, базу данных, серверную часть, консольный клиент и веб-приложение без постоянного пересмотра базовых решений.

Переход к следующему этапу:
Требования, термины, сущности, связи и основные правила достаточно ясны для проектирования API и схемы хранения.

Задачи верхнего уровня:

- регистрация и вход;

Переход к следующему этапу:
Серверная часть достаточно стабильна, чтобы проверять реальные сценарии через внешний консольный клиент.

Переход к следующему этапу:
